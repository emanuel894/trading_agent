The May 16 8-K's May 12 charter/bylaw exhibits remain a credible free legal
reconciliation step. Under **005**, later retrieval/publication is not a reason
to reject a genuine statement about earlier valid facts. Equally, a May 12
change cannot simply be assigned to May 1/9. The exhibits must actually identify
the prior class/provisions and applicable effective history; they have not been
inspected in this task. New SEC, issuer-IR and charter requests were denied by the
runtime proxy. These are access limits, not evidence that the exhibits lack
useful facts or that a paid dataset is necessary.

Current SEC ticker lists or a current issuer page would not establish historical
class completeness. No current-universe substitution, filing-to-filing carry

### Massive historical reference

The prior four-date capture remains admissible at its documented date-level
scope. Current official [client source][massive-client] says `date` retrieves

An issuer-wide historical query without ticker/type/exchange prefilters could

would not certify completeness or intraday validity. **No new Massive API call
was made, and all remaining 58 session calls are deferred.** We did not rerun

### QuantConnect/LEAN and Morningstar

Current official documentation/source pins are LEAN
`d4cac37514427c84d40064cecbf3f0e6be4b0137` and Documentation
`697eaf38f1d9b257aabb45e3a3210318276c2212`.

The US Equity Security Master is documented historical daily map/factor data,
New York timezone, approximately 27,500 equities since January 1998. This is
useful for daily symbol/corporate-action lineage, not a source-certified exact
legal interval. [MapFileRow][qc-row] parses eight-character calendar dates;
[MapFile][qc-map] selects the first row ending on/after a query date. A row must
not be misread as a start timestamp. The actual public AAPL map has a future
terminal sentinel, illustrating why engine boundaries are not literal legal
delisting facts. FMBH was absent from the inspected public sample path only;
that is not a claim of absence from the licensed product.

The official live-considerations source says backtest corporate actions occur
at midnight ET, whereas live delivery arrives at 6/7 AM ET. That is an engine
delivery convention, not independently sourced midnight legal effectiveness.
[MapFilePrimaryExchangeProvider][qc-exchange] returns the **last** mapped
exchange without a historical query time; using it directly could substitute a
later exchange for the historical one.

Morningstar separately supplies useful CIK, company/share IDs, type and class
descriptors. Its documentation expressly supports historical universes including
delisted companies; a blanket survivor-only objection would be wrong. However,
coverage is about 8,000 equities, density sparse, with most key updates monthly
and unchanged data carried daily. The primary-share flag selects one class even
if others exist. None of this guarantees an exhaustive issuer-wide legal-class
census, complete effective changes or exact instants for FMBH. No actual FMBH
Morningstar row was acquired.

The published master price table starts at **$600/year** for Quant Researcher;
this is not a verified all-in quote or evidence the dataset solves the blocker.
Dataset rights restrict use to LEAN/internal licensed use; open engine licensing
does not grant dataset rights. No purchase or broad importer is recommended.

## Strongest new lead: Databento Reference Security Master

Official pins: Rust `72316bd104b47a2a9c24d10eb10f6daad9b36735`, Python
`25eef4ee8e66559e2370166a57c20925ce244d49`, DBN
`82f76c1de6f5c8a1f4b3711fac423f88a3f91d67`.

The [Rust security-master schema][db-master] explicitly says:

> The timestamp (UTC) the record details are effective from.

That describes `ts_effective`. It separately defines `ts_record` as record-change
time and `ts_created` as Databento-addition time. Preserve them and our actual
retrieval independently; none is automatically source first publication or
decision-time knowledge. The schema supplies optional CIK, issuer/security/
listing IDs, listing status, primary exchange and other identifiers.
`issuer_id` links securities of a company, while `security_id` links listings.

The [Python client][db-python] and changelog support issuer-ID inputs. That is a
better issuer-wide discovery route than a ticker-only sample. Still unresolved:

- `get_range` filters the selected clock over inclusive start/exclusive end;
  start is mandatory. A query beginning at the cutoff can omit an unchanged
  earlier record. `get_last` is latest-only, not a historical as-of baseline.
- Timestamp encoding/request precision does not demonstrate the native economic
  resolution of every listing/class field. Date-only listing/delisting fields
  also exist. The public Apple fixture uses midnight effective timestamps; it
  cannot certify exact May 2025 FMBH transitions.
- No inspected source guarantees a complete historical baseline, every relevant
  structural update/correction, or every qualifying issuer class. Optional CIK,
  issuer/security IDs and a broad equity code do not by themselves prove legal
  common-class identity. Primary exchange codes need their documented mapping;
  an operating MIC alone is not a primary-listing assertion.
- `allocate_isins=False` explicitly drops rows that would need new allocations.
  That setting cannot be used to claim a complete class census. Default true may
  allocate under ISIN-limited plans. No such request was made; do not infer a
  harmless/free query or recommend creating an entitlement to try it.
- Actual FMBH issuer-wide coverage, product-history start and minimum price were
  not verified. A historical market-data `metadata.get_cost` response would not
  necessarily quote this separate Reference product.

The public Reference fixture contains Apple, **not FMBH**. The public XNAS.ITCH
definition fixture contains NVDA in December 2020 with undefined activation/
expiration, not an FMBH interval. DBN definitions permit undefined activation/
expiration for equities and distinguish event/capture clocks; symbology mapping
intervals are UTC dates. Those samples help test schemas, not the candidate's
facts. Buying/replaying more ITCH data cannot manufacture legal-class completeness.
