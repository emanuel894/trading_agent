ההחלטה שלי

IBKR הוא בסיס מתאים לפרויקט הזה. ישראל מופיעה ברשימת המדינות הנתמכות, והחיבור שנבחר הוא TWS API הרשמי. הזכאות בפועל תלויה באישור החשבון ובהרשאותיו. התוכנית מתייחסת למסחר בניירות אמריקאיים מתוך ישראל, בהתאם לבחירה שלך. רשימת המדינות של IBKR · תיעוד ה־API.

הדרך לשפר את הסיכוי לרווח היא לבחור מעט אסטרטגיות, לבדוק אותן על נתונים שלא שימשו לפיתוח, ולהכניס לחשבון את כל העלויות והסיכונים. אין מודל שאפשר להכתיר מראש כ״הטוב ביותר להרווחת כסף״, ואין הבטחת רווח.

לגרסה הראשונה אני מציע סל מחקר קטן של ETF נזילים ולא ממונפים, קנייה והחזקה או יציאה למזומן, ואותות יומיים. בהמשך נבדוק אם מעבר לשעה או הוספת מניות בודדות משפרים את התוצאה. תדירות מסחר גבוהה מוסיפה עלויות ומורכבות, וצריכה להצדיק את עצמה.

מה מוכן כעת: קוד להרצת הדגמה ומחקר ייחוס, רכיבי סיכון ויומן שנבדקו, ומתאם לבדיקת חיבור לקריאה בלבד ל־IBKR Paper. עדיין אין בחבילה מנוע ששולח עסקאות לברוקר, מודל AI מאומן או שירות 24/7. החיבור האמיתי דורש חשבון ו־TWS במחשב שלך; המחקר דורש נתונים. אלו השלבים הבאים בתוכנית, לא יכולות שכבר הוכחו.

אם החשבון שלך נפתח דרך גורם מתווך, נבדוק את הגישה ל־API, מבנה העמלות והתמיכה של המסלול הקיים. אין צורך לפתוח חשבון נוסף לפני הבדיקה הזו. המדריך מניח Windows; קוד Python עצמו מתאים גם ל־Linux, עם הוראות פקודה בקובץ README.

אין צורך לקנות כעת מחשב עם GPU, מנוי LLM, שרת ענן, TradingView, נתוני L2/L3 או חשבון ברוקר נוסף. מחשב קיים עם SSD ו־16GB זיכרון הוא נקודת התחלה נוחה, כהמלצת תכנון.

סדר ההתקנה — צעד אחר צעד

1. הרץ את החבילה בלי ברוקר

  1. חלץ את Trading_Agent_Starter.zip לתיקייה קבועה, למשל C:\TradingAgent. אל תריץ מתוך חלון ה־ZIP.
  2. הפעל setup_windows.bat. הוא ייצור סביבה מקומית, יעתיק קובץ הגדרות לדוגמה ויריץ את הבדיקות.
  3. התוצאה הצפויה היא Ran 21 tests ולאחר מכן OK. אם מתקבלת שגיאה, עצור ושלח את הטקסט שלה לאחר הסרת פרטים אישיים.
  4. הפעל run_demo.bat. אמורה להופיע הודעה שעובדו 300 נרות יומיים ושהדוח נשמר בתיקיית runs. הנתונים בהדגמה מלאכותיים; כל מספר תשואה שם הוא תוצר הדגמה.

2. התקן את חבילת Python של IBKR

לאחר התקנת קובץ ה־MSI של TWS API, אתר את תיקיית source\pythonclient. בנתיב התקנה רגיל היא עשויה להימצא תחת C:\TWSAPI; בדוק את הנתיב בפועל. פתח Terminal מתוך תיקיית הפרויקט והרץ:

.\.venv\Scripts\python.exe -m pip install "C:\TWSAPI\source\pythonclient"
.\.venv\Scripts\python.exe -c "from ibapi.client import EClient; print('IB API import OK')"

אם התיקייה שונה, החלף את הנתיב בפקודה. ה־SDK יותקן בסביבה המקומית בלבד. אין בחבילה עותק של קוד IBKR, והתקנת התלויות שלו עשויה לדרוש אינטרנט. IBKR דורשת כיום Python 3.11 ומעלה; הבסיס שצורף נבדק כאן על 3.12.14. התקנת SDK ב־Windows · דרישות גרסה.

3. הגדר TWS לקריאה מ־Paper

  1. התחבר ל־TWS באמצעות פרטי ה־Paper ובדוק שמופיע במפורש סימון Paper Trading.
  2. פתח Global Configuration → API → Settings.
  3. סמן Enable ActiveX and Socket Clients. בשלב הזה השאר Read-Only API מסומן: החבילה הנוכחית קוראת נתונים בלבד. הדרכת IBKR הכללית מסירה הגדרה זו לצורך ביצוע פקודות; את שלב הביצוע ניישם בנפרד.
  4. הגדר את יציאת Paper של TWS ל־7497, וגישה מהמחשב המקומי בלבד. אל תפתח יציאה בנתב או גישה ציבורית.
  5. פתח את config\ibkr.local.json. החלף את REPLACE_WITH_YOUR_DU_ACCOUNT במספר ה־Paper המדויק. אין להכניס סיסמה לקובץ.
  6. הפעל check_connection.bat. ב־TWS אשר את החיבור המקומי אם מוצגת בקשה.

מיקום הגדרות API בתיעוד IBKR. החבילה מקבלת רק 127.0.0.1 ויציאת Paper מוכרת, ובודקת בנוסף את החשבון ש־TWS מחזירה. אין להסיר את בדיקת החשבון כדי לעקוף תקלה.

התוצאה הצפויה היא READ_ONLY_CHECK_PASSED. הדוח יכיל גרסת API, אימות התאמת החשבון וספירת פוזיציות ופקודות פתוחות. הצלחה אינה מאשרת זכאות לנתוני זמן אמת או כשירות למסחר אוטומטי. אם הבדיקה נכשלת, בדוק שה־Paper מחובר, שהיציאה תואמת ושמספר client_id אינו תפוס.

4. הורד דגימת נתונים והרץ ייחוס ראשוני

לאחר הצלחת החיבור, ניתן להריץ את הפקודות הבאות מתיקיית הפרויקט:

.\.venv\Scripts\python.exe -m agent history --output runs\history
.\.venv\Scripts\python.exe -m agent research --csv runs\history\SPY_daily.csv

הפקודה מבקשת שנתיים של נרות יומיים ל־SPY, כדוגמת אינטגרציה בלבד. זמינות הנתונים תלויה בהרשאות. נר היום מוסר. הקוד משווה כלל מגמה פשוט, קנייה והחזקה באותה הקצאה התחלתית, מזומן, ועלויות ביצוע מוגדלות. הוא אינו מאמן AI ואינו מחשב תוצאה מלאה הכוללת דיבידנדים, ריבית, מס וסליקה. הרחבה כזו היא חלק משלב המחקר.

מה להעביר להמשך עבודה: את קובץ connection_report.json לאחר שעיינת בו והסרת מידע אישי, את מערכת ההפעלה שלך ואת הודעות השגיאה אם יש. אין לשלוח סיסמה, קוד MFA, מסמכי זיהוי או את קובץ ההגדרות המקומי. הדוח משמיט יתרות וממסך מספרי חשבון בתבניות נפוצות, אך עדיין נדרש לעיין בו.

המחקר וההנדסה מתקדמים במקביל. אם אסטרטגיה אינה מראה יתרון, פוסלים אותה. לא מפצים על כך בהגדלת מינוף, בהסרת חסימות או בבחירה חוזרת של פרמטרים לפי התוצאה שרוצים לראות.

איך הסוכן יעבוד ביום רגיל

  1. לפני מסחר: בדיקת לוח הבורסה, נתונים, חיבור ומצב החשבון. אי־התאמה תחסום הגדלת סיכון.
  2. החלטה: האסטרטגיה תחשב יעד לפוזיציה, לרבות האפשרות להישאר במזומן. כל החלטה תירשם עם הנתונים וגרסת המודל.
  3. סיכון: רכיב נפרד יבדוק מזומן פנוי, התחייבויות ופקודות ממתינות, חשיפה, נזילות, מחיר ומגבלות הפסד.
  4. ביצוע: המנוע ישלח פקודות Paper מאושרות, יטפל במילויים חלקיים ויעדכן את המצב מול הברוקר. אין צורך באישור שלך לכל עסקה.
  5. בקרה: תקלה תפעיל מצב עצירה מוגדר והתראה. חידוש אחרי עצירה קשה או החלפת מודל הם פעולות נפרדות מהמסחר השוטף.
  6. סוף היום: התאמת פוזיציות וכספים, סיכום פעילות, בדיקת חריגות וגיבוי.

24/7 פירושו זמינות וניטור רציפים. ב־V1 נבצע פקודות בשעות המסחר הרגילות בלבד, לפי לוח הבורסה: בדרך כלל 09:30–16:00 בזמן ניו יורק, עם חגים וימים מקוצרים. השעה בישראל משתנה בתקופות מעבר שעון; לא נשתמש בהפרש קבוע. לוח NYSE.

IBKR מתעדת אתחול יומי ואימות שבועי שעשוי לדרוש כניסה ידנית מחדש. לכן היעד הוא אוטונומיה בהחלטות ובביצוע לצד תחזוקה והתערבות בתקלות. נתכנן זאת במפורש, בלי לעקוף MFA. השירות יפעל על מחשב או שרת ייעודי; השיחה הזו אינה שרת מסחר קבוע. אימות ואתחול ב־IBKR.

LLM יוכל בהמשך לסווג חדשות ולהפיק דוחות. הוא לא יחזיק הרשאה חופשית לשינוי מגבלות או לשליחת פקודות. גם אסטרטגיה המבוססת על AI תעבור דרך אותו מנוע סיכונים.

עלות, סיכון ותנאי הצלחה

עכשיו

הקוד וההדגמה אינם דורשים שירות בתשלום. השתמש במחשב הקיים. הפעלת API ונתוני שוק כפופות לתנאי חשבון IBKR.

אחרי חיבור

בחר מנוי נתונים רק לאחר בירור הרשאות API וצרכי האסטרטגיה. שרת רציף ייבחר לאחר שהרצה מקומית יציבה.

נבדוק מנוי נתוני מניות אמריקאיות שכולל את הבורסות וה־quotes הדרושים דרך ה־API. מחיר ומעמד מקצועי/לא מקצועי נקבעים לפי החשבון; תצוגת מחיר בזמן אמת במסך אינה כשלעצמה הוכחה להרשאות API מתאימות. נתונים מושהים יכולים לעזור בבדיקת חיבור, אך אינם בסיס למדידת תגובה בזמן אמת. מחירון נתוני IBKR.

לשלב השרת אפשר להקצות לצורכי תכנון כ־40–150 דולר בחודש למחשב ענן קטן ושירותים בסיסיים, לפני נתונים וגיבוי מתקדם. זהו אומדן הנדסי, לא הצעת ספק. עמלות, המרות מטבע ויתר חיובי המסחר ייכנסו למודל העלויות לפי החשבון שלך. עמלות מניות רשמיות.

ההון משנה את הכדאיות: עלות של 100 דולר בחודש היא 1,200 דולר לשנה — 12% מהון של 10,000 דולר או 2.4% מהון של 50,000 דולר, עוד לפני עלויות מסחר ומס. לכן נצטרך להגדיר הון עתידי, תקציב חודשי והפסד מרבי נסבל לפני שנקבע את היקף המערכת. סכום ה־10,000 דולר בהדגמה הוא כסף וירטואלי לצורכי בדיקה בלבד.

הסוכן יצטרך לכבד את סוג החשבון, הסליקה ומגבלות הברוקר בפועל. אין להניח שכללי PDT הישנים חלים ללא שינוי: FINRA מתעדת כללים חדשים מ־4.6.2026 ותקופת מעבר לברוקרים עד 20.10.2027. לפני מסחר תוך־יומי יש לברר עם IBKR איזה משטר חל על החשבון שלך. הסבר FINRA המעודכן.

  • הוכחה תפעולית: אין כפילויות, אין פערי פוזיציה לא מוסברים, אין מסחר על מצב לא ידוע, ועצירה נשמרת גם אחרי אתחול.
  • הוכחה כלכלית: יתרון לאחר עלויות ביחס לייחוס מתאים, במספר תקופות ובתרחישים מחמירים, תוך הצגת טווחי אי־ודאות ותוצאות הניסויים שנכשלו.
  • הבחנה בין Paper ל־Live: מילויי Paper מדומים. הם מאפשרים לבחון את המערכת אך אינם מוכיחים מחיר ביצוע, תור פקודות או השפעה על השוק בכסף אמיתי. מגבלות Paper.
  • סיכון אישי: לינה עם פוזיציה יוצרת סיכון פערי פתיחה; נכסים בדולר יוצרים גם חשיפת דולר–שקל. סף עצירה הוא טריגר לפעולה, ולא הבטחה שההפסד לא יחרוג ממנו.

לפני Live יש לברר דיווח ומיסוי בישראל בהתאם למבנה החשבון והפעילות. התוכנית אינה קובעת שיעור מס או פטור מרישוי, ומתייחסת למסחר בחשבון אישי בלבד. ניהול כספים של אחרים מחייב בחינה נפרדת.
